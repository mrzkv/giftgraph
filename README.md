# Telegram Gift Graph

Утилита строит направленный граф видимых подарков Telegram через пользовательскую
сессию Kurigram. Чат задаёт стартовый список участников; дальше сборщик читает
подарки в профилях и переходит к известным дарителям до заданной глубины.
История сообщений чата для этого не загружается. Обычный Telegram-бот не нужен.

Сборщик `crawl` работает только на чтение: не отправляет сообщения, реакции,
уведомления о прочтении, не вступает в чаты и не запускает авторизацию.
Допустимые RPC ограничены обязательным списком в коде. Отдельный скрипт
`generate_session.py` нужен для первоначального входа, который вы запускаете
сами: он создаёт новую авторизованную сессию, видимую в списке устройств Telegram.

## Весь путь от установки до графа

1. Скачайте проект и установите его в окружение Python.
2. Проверьте установку на вымышленных данных через `demo`.
3. Скопируйте `.env.example` в `.env` и получите свои `API_ID` / `API_HASH`.
4. Один раз создайте `userbot.session` по QR-коду. Если готовая совместимая сессия
   уже есть, используйте её и пропустите получение ключей и создание новой.
5. Запустите `crawl` для одного пользователя или чата.
6. Откройте GraphML / JSON; при необходимости продолжите очередь через `resume`.

Все команды ниже выполняются из папки проекта — там, где лежат `pyproject.toml`
и `generate_session.py`. На странице репозитория GitHub выберите **Code → Download ZIP**, распакуйте
архив и откройте терминал в папке с этими файлами. Перейти в папку можно командой
`cd social-graph-tg` (замените имя на имя распакованной папки).

## 1. Установка без `uv`: Python, `venv` и `pip`

Нужен **Python 3.11 или новее**. Установить его можно с [python.org](https://www.python.org/downloads/).
Проверьте версию: `python3 --version` в macOS / Linux или `py -3 --version` в Windows.
`venv` создаёт отдельное окружение с зависимостями проекта; установка локального
проекта через `pip` также создаёт команду `giftgraph`.
См. [venv](https://docs.python.org/3/library/venv.html) и
[установку локальных проектов через pip](https://pip.pypa.io/en/stable/topics/local-project-installs/).

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install ".[qr]"
python -m giftgraph --help
```

Дополнение `qr` устанавливает поддержку QR-кода для создания сессии.
После активации окружения команды `python` и `giftgraph` относятся к этому проекту.
В новом окне терминала снова перейдите в папку проекта и выполните
`source .venv/bin/activate`. Завершить работу в окружении можно командой `deactivate`.

### Windows: PowerShell

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install ".[qr]"
.\.venv\Scripts\python.exe -m giftgraph --help
```

Здесь Python вызывается по полному пути внутри окружения: активация и изменение
политики выполнения PowerShell не требуются. Во всех следующих примерах заменяйте
начальное `python` на `.\.venv\Scripts\python.exe`. Например:

```powershell
.\.venv\Scripts\python.exe generate_session.py
.\.venv\Scripts\python.exe -m giftgraph crawl --user "@username"
```

Если вы уже активировали окружение подходящим для своего терминала способом,
можно использовать обычные `python` и `giftgraph`. В PowerShell username с `@`
передавайте в кавычках, как в примерах: `--user "@username"`. Без кавычек `@name`
имеет [специальный смысл для PowerShell](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_splatting).

### Если предпочитаете `uv`

```bash
uv sync --extra qr
uv run python -m giftgraph --help
```

Дальше вместо `python -m giftgraph ...` используйте `uv run giftgraph ...`,
а вместо `python generate_session.py` — `uv run python generate_session.py`.
`uv` использует версии из `uv.lock`; установка через `pip` использует ограничения
из `pyproject.toml`, поэтому точные версии могут отличаться.

### Три способа запуска одной утилиты

После установки и активации окружения все три варианта передают одинаковые
аргументы одному CLI; для третьего нужен установленный `uv`:

```bash
python -m giftgraph crawl --user "@username"
giftgraph crawl --user "@username"
uv run giftgraph crawl --user "@username"
```

Если команду `giftgraph` не находит терминал, используйте `python -m giftgraph`
из нужного окружения; для этого варианта отдельная команда в `PATH` не нужна.

## 2. Проверка установки без Telegram

```bash
python -m giftgraph demo --export outputs/demo.graphml --export outputs/demo.json
```

`demo` не требует API-ключей или сессии и не подключается к Telegram. Оно создаёт
вымышленные данные: при стандартной глубине 2 получаются 3 вершины и 4 ребра.
Появятся база `data/demo.db` и два файла в `outputs`. Это подтверждает, что CLI,
SQLite и экспорт работают, до входа в аккаунт.

## 3. Файл настроек и ключи Telegram API

Если `.env` ещё нет, создайте его из шаблона. Существующий файл сохраняйте,
редактируйте его вместо повторного копирования.

macOS / Linux:

```bash
cp .env.example .env
```

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Для **создания новой сессии** нужны собственные ключи приложения Telegram.
Это `api_id` и `api_hash`, а не токен BotFather.

1. Откройте [my.telegram.org/apps](https://my.telegram.org/apps) в браузере.
2. Войдите по номеру своего Telegram-аккаунта и введите полученный код подтверждения.
3. Откройте **API development tools**. Если приложение ещё не создано, заполните
   форму: задайте название приложения и короткое имя, выберите подходящую платформу
   (например, Desktop) и заполните остальные запрашиваемые поля.
4. На странице приложения найдите **App api_id** и **App api_hash**.
5. Откройте `.env` в редакторе, раскомментируйте `API_ID` и `API_HASH` и укажите
   свои значения. `API_ID` — положительное целое число; `API_HASH` — строка
   из 32 шестнадцатеричных символов.

Порядок получения ключей описан в [официальной инструкции Telegram](https://core.telegram.org/api/obtaining_api_id).
Не создавайте приложение повторно, если ключи для вашего аккаунта уже получены.

```dotenv
API_ID=YOUR_API_ID
API_HASH=YOUR_API_HASH
```

Здесь `YOUR_API_ID` и `YOUR_API_HASH` — обозначения: **замените их своими значениями**,
в таком виде скрипт их не примет. Остальные параметры из `.env.example` можно
оставить без изменений. Файл `.env` с ключами не публикуйте: он исключён из Git.
Если ключи уже заданы в переменных окружения терминала, они имеют приоритет над `.env`.

## 4. Создание `userbot.session` по QR-коду

Если готовая авторизованная сессия Kurigram уже есть, положите её в папку проекта
или передавайте её путь через `--session`. Сборщик не создаёт сессию автоматически.

Для нового входа:

```bash
python generate_session.py
```

1. Скрипт читает `.env` **рядом с `generate_session.py`** и показывает QR-код в терминале.
2. Откройте Telegram на телефоне, где уже выполнен вход в нужный аккаунт.
3. Перейдите в **Настройки → Устройства → Подключить устройство** / **Link Desktop Device**.
   Название пункта зависит от языка и версии приложения.
4. Отсканируйте QR-код из терминала и подтвердите вход, если Telegram попросит.
5. Если включена двухэтапная аутентификация, введите облачный пароль в запросе
   терминала. Это пароль аккаунта, а не `API_HASH`.
6. После сообщения об успешном создании сессии скрипт завершится. В папке проекта
   появится `userbot.session`.

Скрипт использует вход по QR-коду, а не по коду из SMS. Для чтения другого файла
настроек можно передать `python generate_session.py --env-file .env.custom`.
`python generate_session.py --help` показывает справку без входа в аккаунт.
Если готовый корректный `userbot.session` уже найден, повторный запуск использует
его без новой авторизации и без запроса API-ключей.

Проверить наличие файла локально:

```bash
python -c "from pathlib import Path; print(Path('userbot.session').is_file())"
```

`True` означает, что файл есть; это не сетевой тест действительности авторизации.
Для готовой поддерживаемой сессии ключи обычно больше не требуются при сборе.
Файл сессии даёт доступ к аккаунту: храните его локально и не добавляйте в GitHub
или публикуемый архив. `.session`, `.env`, базы и результаты сбора исключены из Git.

## 5. Первый сбор и результат

Замените `@username` на нужный профиль. Для первого запуска можно ограничить объём:

```bash
python -m giftgraph crawl --user "@username" --depth 1 --max-nodes 100 --max-gifts 100 --max-pages 20 --delay 1
```

Без `--export` получится `outputs/username.graphml`. Для чата используйте `--chat`
вместо `--user`; в этом примере стартовыми будут до 10 участников:

```bash
python -m giftgraph crawl --chat "@example_chat" --seed-limit 10 --depth 1 --max-nodes 100 --max-gifts 100 --max-pages 20
```

Передайте **ровно одну** цель: `--chat` или `--user`, один раз. Принимаются числовые
ID, usernames с `@` или без него и публичные ссылки `https://t.me/username`.
Для групп используйте Telegram ID группы, например `-1001234567890`.
Аккаунт должен уже иметь доступ к чату и его списку участников: утилита никуда
не вступает. Telegram может ограничить доступный список участников и подарков.

Для двух форматов и отдельных подписей к подаркам:

```bash
python -m giftgraph crawl --user "@username" --export outputs/graph.graphml --export outputs/graph.json --gift_description
```

В `outputs` сохранятся графы и `graph.gift_descriptions.json`. GraphML можно открыть,
например, в Gephi; JSON — в редакторе или своём скрипте. В `data/gifts.db` находятся
наблюдения и очередь обхода; состояние и повторный экспорт доступны без нового сбора:

```bash
python -m giftgraph status
python -m giftgraph resume
python -m giftgraph export --out outputs/graph.json
```

`resume` обновляет экспорт по сохранённым путям. После `Ctrl+C` прогресс остаётся
в базе; `resume` продолжает сохранённую очередь. Если файлов сессии несколько,
передайте нужный явно: `python -m giftgraph resume --session ./userbot.session`.

## Параметры `crawl`

Полный пример со своими лимитами и путями (переносы строк ниже — для macOS / Linux;
в PowerShell можно записать команду одной строкой):

```bash
python -m giftgraph crawl --chat "@example_chat" \
  --seed-limit 100 --depth 2 --max-nodes 1000 --max-gifts 500 \
  --max-pages 2000 --delay 1 \
  --export outputs/graph.graphml \
  --session ./userbot.session \
  --gift_description
```

| Параметр | По умолчанию | Что ограничивает или выбирает |
| --- | --- | --- |
| `--chat` / `--user` | Обязательная цель | Один чат или один пользователь |
| `--seed-limit` | `100` | Максимум стартовых участников чата; для `--user` не нужен |
| `--depth` | `3` | Число переходов по связям даритель → получатель |
| `--max-nodes` | `3000` | Максимум вершин графа, включая стартовые |
| `--max-gifts` | `1000` | Максимум видимых подарков на один профиль |
| `--max-pages` | `2000` | Общий бюджет страниц подарков на один вызов команды |
| `--page-size` | `100` | Размер страницы подарков, от 1 до 100 |
| `--delay` | `1` | Минимальная пауза между запросами к Telegram, в секундах |
| `--export` | `outputs/<цель>.graphml` | Файл `.graphml` или `.json`; можно указать несколько раз |
| `--session` | Автопоиск в текущей папке | Путь к готовому файлу сессии |
| `--gift_description` | Выключен | Сохранить доступные подписи к подаркам отдельным JSON |

Без `--export` для `--user "@username"` создаётся `outputs/username.graphml`, для
`--chat "@example_chat"` — `outputs/example_chat.graphml`. При числовой цели
используется актуальный username, если Telegram его сообщил, иначе ID. Повторный
экспорт по тому же пути заменяет файл; сами запуски отдельно хранятся в SQLite. `--db` задаёт базу, по умолчанию `data/gifts.db`.

Без `--session` сначала выбирается `userbot.session` в текущей папке. Если его нет,
выбирается единственный файл `*.session` там же. Если файлов нет или их несколько,
утилита просит явно указать путь и завершается без входа в Telegram.

Стартовые пользователи имеют `depth=0`. Дарители из их подарков получают `depth=1`
и так далее. Профили на предельной глубине сохраняются, но уже не запрашиваются.
Граф раскрывается по наблюдаемым входящим подаркам: это не полный список всех
исходящих подарков аккаунта.

## Зачем нужен `--max-pages`

Список подарков в профиле приходит страницами через
[`payments.getSavedStarGifts`](https://core.telegram.org/method/payments.getSavedStarGifts).
При `--page-size 100` тысяча подарков одного человека может потребовать десять
запросов. При большом графе это уже тысячи запросов, поэтому `--max-pages 2000`
ограничивает их общий объём за один вызов команды.

Задержка `--delay` применяется ко всем запросам данных: поиску цели, участникам
и страницам подарков. При `FLOOD_WAIT` Telegram дополнительное ожидание выполняется
автоматически.

Это **страницы подарков**, а не сообщения чата. Чтение участников чата выполняется
отдельно и в этот бюджет не входит. Подарки с неизвестным дарителем тоже учитываются
в лимите `--max-gifts`, поскольку они присутствуют в полученной странице.

При исчерпании бюджета очередь и курсоры сохраняются. Продолжить:

```bash
python -m giftgraph status
python -m giftgraph resume
```

`resume` получает новый бюджет страниц, но использует те же лимиты, что были
сохранены при создании обхода. Изменение `.env` не меняет уже начатый запуск.
Чтобы сменить лимиты, начните новый `crawl`. При достижении `--max-nodes` или
обрезании подарков профиля по `--max-gifts` результат помечается как частичный.

## Что сохраняется в графе

Вершина содержит `user_id` — Telegram ID строкой без потери точности, `username`
(если он доступен) и `depth`. Технические `id`, `kind`, `label` и `scan_state`
позволяют различать сущности и видеть состояние обхода.

Каждый наблюдаемый подарок — отдельное направленное ребро, поэтому между двумя
людьми может быть несколько рёбер.

| Поле ребра | Значение |
| --- | --- |
| `sender_id` / `recipient_id` | Telegram ID отправителя и получателя |
| `source` / `target` | Ссылки на вершины графа |
| `gift_id` | ID обычного подарка в каталоге или ID конкретного коллекционного экземпляра |
| `date` | Время дарения: Unix timestamp, секунды UTC |
| `stars` | Доступная цена обычного подарка в Stars; неизвестная цена — `null` |
| `gift_title` | Название; для коллекционного — вместе с `#номером` |
| `gift_number` / `gift_slug` | Номер и slug коллекционного подарка, если доступны |
| `id` / `gift_key` | ID события дарения и внутренний ключ подарка |

Для обычного подарка `stars` — цена из наблюдаемого каталога Telegram, а не
доказательство суммы, уплаченной в прошлом. Для коллекционного подарка исходная
цена не предоставляется: `stars=null`, даже если API сообщает оценку или цену
перепродажи. См. [обычный подарок](https://core.telegram.org/constructor/starGift)
и [коллекционный подарок](https://core.telegram.org/constructor/starGiftUnique).
Когда название обычного подарка отсутствует, используется эмодзи стикера или
`Gift <ID>`; название не угадывается.

Для коллекционных подарков ребро строится только по доступным
[данным первоначального дарения](https://core.telegram.org/constructor/starGiftAttributeOriginalDetails).
Текущее владение подарком не означает дарение нынешнему владельцу. Владение
сохраняется отдельно, как и события с неизвестным или скрытым отправителем:
они не создают вымышленных связей. В GraphML эти наблюдения и метаданные находятся
в атрибутах графа. Неизвестные значения в JSON — `null`, в GraphML соответствующий
атрибут отсутствует.

Сохранённый граф можно экспортировать повторно без Telegram:

```bash
python -m giftgraph export --out outputs/graph.json
python -m giftgraph export --out outputs/graph.graphml
```

## Подписи к подаркам

`--gift_description` (также `--gift-description`) включает сбор доступного текста,
который отправитель приложил к подарку. Он не читает историю личных сообщений.
Без флага текст не сохраняется.

Рядом с `outputs/graph.graphml` создаётся `outputs/graph.gift_descriptions.json`:

```json
{
  "user:123:message:456": "С днём рождения!"
}
```

Ключ — `id` события дарения, значение — подпись. Один и тот же обычный `gift_id`
встречается многократно с разными подписями, поэтому использовать его как
единственный ключ нельзя. Подписи не включаются в рёбра графа. Файл содержит все
собранные доступные подписи, включая события, не вошедшие в граф из-за его ограничений. При `resume`
режим сбора подписей наследуется от исходного запуска. Уже сохранённые подписи
можно выгрузить командой `export --out outputs/graph.graphml --gift_description`.

## Настройки в `.env`

CLI автоматически читает `.env` из текущей рабочей папки. `.env.example` содержит
указанные выше значения по умолчанию и служит шаблоном для новой установки.
Скрипт создания сессии ищет `.env` рядом с собой; при запуске из папки проекта
оба варианта используют один файл.
Приоритет: **явные флаги CLI → переменные окружения → `.env` → встроенные значения**.

```dotenv
GIFTGRAPH_DB=data/gifts.db
GIFTGRAPH_OUTPUT_DIR=outputs
GIFTGRAPH_SEED_LIMIT=100
GIFTGRAPH_DEPTH=3
GIFTGRAPH_MAX_NODES=3000
GIFTGRAPH_MAX_GIFTS=1000
GIFTGRAPH_MAX_PAGES=2000
GIFTGRAPH_PAGE_SIZE=100
GIFTGRAPH_DELAY=1
GIFTGRAPH_GIFT_DESCRIPTION=false
# GIFTGRAPH_SESSION=./userbot.session
# API_ID=
# API_HASH=
```

Необязательная `GIFTGRAPH_SESSION` отключает автопоиск и задаёт конкретный путь.
Для существующей поддерживаемой сессии `API_ID` и `API_HASH` обычно не нужны.
Все относительные пути считаются от рабочей папки, включая пути из другого
файла конфигурации. Поддерживаются кавычки и комментарии; переменные `${NAME}`
и команды оболочки внутри значений не выполняются и не подставляются.

```bash
python -m giftgraph crawl --user "@username" --depth 2
python -m giftgraph --env-file .env.custom crawl --user "@username"
```

`--env-file` можно поставить и после команды. Отсутствие обычного `.env` допустимо;
отсутствие явно указанного файла считается ошибкой. `.env` и файлы сессий исключены
из Git. Режим чтения аккаунта отключить настройкой нельзя.

## Если что-то не получилось

| Симптом | Что проверить |
| --- | --- |
| `python` / `python3` / `py` не найдены | Установите Python 3.11+; в Windows используйте `py -3`, в macOS / Linux — `python3` при создании окружения. |
| `No module named giftgraph` | Установите проект из его папки: `python -m pip install ".[qr]"`. Запускайте тем же Python, которым установили. |
| `No module named pip` в старом окружении `uv` | Выполните `python -m ensurepip --upgrade`, затем `python -m pip install ".[qr]"`; свежее окружение `python -m venv` обычно уже содержит `pip`. |
| Не хватает `qrcode` или не показывается QR-код | Установите дополнение `qr`: `python -m pip install ".[qr]"`. Увеличьте окно терминала, чтобы QR-код помещался целиком. |
| Неверный `API_ID` / `API_HASH` | Скопируйте значения приложения с `my.telegram.org/apps`, уберите примеры `YOUR_...`; проверьте также переменные окружения, имеющие приоритет над `.env`. |
| Telegram просит пароль при входе | Введите облачный пароль двухэтапной аутентификации своего аккаунта в запросе терминала. |
| Файл сессии не найден | Запустите `generate_session.py` либо укажите готовую сессию через `--session /path/to/file.session`; проверьте текущую рабочую папку. |
| Найдено несколько `.session` | Выберите одну через `--session`. Если в папке есть `userbot.session`, он имеет приоритет при автопоиске. |
| Сессия повреждена, несовместима или отозвана | Нужна действующая пользовательская сессия Kurigram; чужие форматы автоматически не конвертируются. Готовый файл не перезаписывается автоматически. |
| Username не найден / нет доступа к участникам | Проверьте username и доступ аккаунта к группе. Скрытый или недоступный список утилита не открывает. |
| `FLOOD_WAIT` | Дождитесь указанной паузы: сборщик повторит запрос автоматически. При необходимости уменьшите объём обхода и увеличьте `--delay` для нового запуска. |
| PowerShell не разрешает `Activate.ps1` | Активация не обязательна: используйте `.\.venv\Scripts\python.exe -m giftgraph ...` напрямую. |

Если первый вход по QR был прерван и осталась **неполная** сессия, помощник
не перезаписывает её и не начинает вход повторно. Закройте помощник и другие
процессы, использующие этот файл. Переместите неполный `userbot.session` и
имеющиеся файлы `userbot.session-journal`, `userbot.session-wal`,
`userbot.session-shm` в `work/session-backup/` (эта папка исключена из Git).
Затем повторите `python generate_session.py`. Это относится к незавершённому
первому входу; готовую рабочую сессию перемещать не требуется.

## Проверки для разработки

Обычная установка включает зависимости для сборщика и QR-входа. Для тестов и
линтера дополнительно установите `dev` в том же окружении:

```bash
python -m pip install -e ".[dev,qr]"
python -m pytest
python -m ruff check src tests
```

С `uv` эквивалентная подготовка — `uv sync --extra dev --extra qr`, затем
`uv run pytest` и `uv run ruff check src tests`. Все автоматические проверки
используют локальные данные и подмены API; настоящая авторизация в них не запускается.

`demo` использует собственные настройки: глубина 2, максимум 500 вершин,
нулевая задержка и база `data/demo.db`. Настройки `.env` для обхода на него
не влияют; явные флаги работают.
